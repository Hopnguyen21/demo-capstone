I. ĐỊNH VỊ NỀN TẢNG & KIẾN TRÚC CÔNG NGHỆ (SMARTFARM PLATFORM)
🏛️ ĐỊNH VỊ CỐT LÕI: MULTI-TENANT SMART AGRICULTURE SAAS PLATFORM
SmartFarm là Nền tảng Nông nghiệp Thông minh đa người thuê (Cloud SaaS) toàn diện, phục vụ đồng thời nhiều Hợp tác xã / Doanh nghiệp nông nghiệp trên một hạ tầng đám mây duy nhất. Nền tảng kết hợp mạng lưới viễn thám thực địa LoRa cự ly xa, tự động hóa điều khiển tưới tiêu vi khí hậu thích ứng theo thời kỳ sinh trưởng của cây trồng và Trợ lý AI Nông học VietGAP/GlobalGAP.
 
1. Phân cấp 4 Cấp Actor trên Platform
Actor Role
Cấp Quyền
Phạm Vi Quản Trị & Nhiệm Vụ Trên Nền Tảng
Platform Admin
Platform-wide
Quản trị toàn bộ nền tảng, duyệt tài khoản Tenant, thiết lập thư viện giống cây & quy trình sinh trưởng VietGAP mẫu (crops, growth_profiles), giám sát tài nguyên máy chủ và bảo mật toàn sàn.
Platform Technician
Platform Staff
Đội ngũ kỹ sư hiện trường; cấp phát (provisioning) thiết bị, rà quét dải sóng LoRa 433MHz, nạp Whitelist MAC vào Gateway ESP32, chẩn đoán lỗi phần cứng và xử lý thay thế 1-đổi-1 (Hot-swap).
Farm Owner (Tenant)
Tenant Root
Khách hàng thuê nền tảng; sở hữu và quản trị một hoặc nhiều Trang trại (Farm), phân lô đất (Field), nhà màng (Zone), kích hoạt vụ mùa, tinh chỉnh ngưỡng vi khí hậu, thiết lập luật tưới và duyệt áp dụng khuyến nghị AI.
Farmer / Farm Worker
Tenant Member
Nhân công trực tiếp ngoài đồng thuộc Tenant; xem số liệu cảm biến Zone được phân công, nhận thông báo đẩy cảnh báo khẩn cấp và kích hoạt lệnh tưới thủ công khi được phân quyền.
 
2. Mô hình Phân cấp Tài nguyên & Cơ chế Crop-aware
• Phân cấp tổ chức chuẩn GIS: SmartFarm Platform ➔ Tenant (Farm Owner) ➔ Farms (1 hoặc nhiều Trang trại) ➔ Fields (Lô đất) ➔ Zones (Nhà màng) ➔ Crop & Growth Stages ➔ IoT Hardware (Gateways, Sensor Nodes, Actuators).
• Cơ chế thích ứng theo cây trồng (Crop-aware Monitoring & Control): Hệ thống quản lý dữ liệu 4 tầng độc lập chuẩn CSDL Data.txt: crops ➔ crop_varieties ➔ growth_profiles ➔ growth_stages ➔ environmental_requirements. Khi cây chuyển thời kỳ sinh trưởng (ví dụ: Cây non ➔ Ra hoa ➔ Nuôi trái), hệ thống tự động cập nhật dải ngưỡng vi khí hậu tối ưu mà không cần nhập thủ công.

III. ĐẶC TẢ CHI TIẾT THEO NHÓM
🔐  NHÓM 1: AUTH — XÁC THỰC & PHIÊN LÀM VIỆC
Quản lý danh tính người dùng, JWT Token, phiên đăng nhập và khôi phục mật khẩu.
  #1     POST   /api/v1/auth/login
Xác thực người dùng, cấp JWT Access Token (1h) và Refresh Token (30 ngày), đồng thời cập nhật FCM Token cho push notification.
1. Input
{
  "email": "owner@smartfarm.vn",
  "password": "Password123!",
  "fcmToken": "fcm_token_chuỗi... (tùy chọn)"
}
2. Output
{
  "accessToken": "eyJhbGciOiJIUzI1NiIs...",
  "refreshToken": "d7a8e9f2-...",
  "expiresIn": 3600,
  "tokenType": "Bearer",
  "user": { "id": "u-101", "role": "FarmOwner", "tenantId": "tenant-dalat-505" }
}
3. Validate
• email: Bắt buộc, chuẩn RFC 5322.
• password: Bắt buộc, 6–100 ký tự.
4. Business Rule
• BR-AUTH-01: Tài khoản phải có status = Active.
• BR-AUTH-02: BCrypt/Argon2 hash. Sai > 5 lần → Khóa 15 phút.
• BR-AUTH-03: JWT Claims bắt buộc chứa sub, role, tenantId.
5. Exception
• 401 Unauthorized: Sai email / mật khẩu.
• 403 Forbidden: Tài khoản bị khóa.
 
  #2     POST   /api/v1/auth/logout  ★ MỚI
Vô hiệu hóa Refresh Token hiện tại, xóa FCM Token khỏi server để ngừng nhận push notification.
1. Input
// Header: Authorization: Bearer {accessToken}
// Body (tùy chọn):
{
  "refreshToken": "d7a8e9f2-...",
  "revokeAllDevices": false
}
2. Output
{
  "message": "Đăng xuất thành công.",
  "revokedAt": "2026-09-20T15:00:00Z"
}
3. Validate
• accessToken hợp lệ trong Header.
4. Business Rule
• BR-LOGOUT-01: Thêm Access Token vào Blacklist Redis (TTL = thời gian còn lại).
• BR-LOGOUT-02: Xoá bản ghi Refresh Token trong DB.
• BR-LOGOUT-03: Nếu revokeAllDevices = true → Thu hồi tất cả phiên trên mọi thiết bị.
5. Exception
• 401 Unauthorized: Token không hợp lệ.
 
  #3     POST   /api/v1/auth/refresh  ★ MỚI
Cấp Access Token mới bằng Refresh Token còn hiệu lực mà không cần đăng nhập lại.
1. Input
{
  "refreshToken": "d7a8e9f2-1b3c-4e5a-9f8d-7c6b5a4e3d2c"
}
2. Output
{
  "accessToken": "eyJhbGciOiJIUzI1NiIs... (mới)",
  "expiresIn": 3600
}
3. Validate
• refreshToken: Bắt buộc, UUID hợp lệ.
4. Business Rule
• BR-REFRESH-01: Refresh Token phải chưa hết hạn và chưa bị thu hồi.
• BR-REFRESH-02: Rotate Refresh Token — cấp token mới, vô hiệu token cũ (One-time use).
5. Exception
• 401 Unauthorized: Refresh Token hết hạn hoặc đã bị thu hồi.
 
  #4     POST   /api/v1/auth/forgot-password  ★ MỚI
Gửi email chứa OTP 6 số hoặc link đặt lại mật khẩu đến địa chỉ email đã đăng ký.
1. Input
{
  "email": "owner@smartfarm.vn"
}
2. Output
{
  "message": "Email đặt lại mật khẩu đã được gửi.",
  "expiresInMinutes": 15

• 400 Bad Request: Số lượng xuất vượt tồn kho.
 
  #99     GET   /api/v1/farms/{farmId}/tasks  ★ MỚI
Lấy danh sách công việc thực địa cần làm trong trang trại (phân công cho Farmer).

2. Output

  ]
}
3. Validate
• status: [Pending, InProgress, Done, Cancelled].
4. Business Rule
• Farmer chỉ thấy task được phân công cho mình.
5. Exception
• 404 Not Found: Không tìm thấy Farm.
 
  #100     POST   /api/v1/farms/{farmId}/tasks  ★ MỚI
Tạo công việc thực địa mới, gán cho Farmer và thiết lập deadline.

4. Business Rule
• BR-TASK-01: Gửi FCM Push Notification cho Farmer được phân công.
5. Exception
• 400 Bad Request: dueDate trong quá khứ.
 
  #101     PUT   /api/v1/farms/{farmId}/tasks/{taskId}  ★ MỚI

• BR-TASK-02: Khi Done → Gửi thông báo FCM cho FarmOwner xem xét.
5. Exception
• 403 Forbidden: Cố cập nhật task không được giao.
 
  #102     GET   /api/v1/farms/{farmId}/cash-flow-report
Hạch toán dòng tiền vụ mùa: doanh thu, chi phí điện/nước/vật tư/nhân công, lợi nhuận ròng.

5. Exception
